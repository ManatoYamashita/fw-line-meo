# スクリーンショット取得

撮る用途は 2 つあり、**必要な承認が違う**。混同しない。

| 用途 | 目的 | 承認 | 対象ブランチ |
|---|---|---|---|
| **画面の取材** | 図解の節 0.5 へ入れる。「この処理はこの画面のこの操作から起きる」を見せる | 既存の起動済み環境で画面を開くだけなので**不要** | 画面が変わらないなら**現行の dev / localhost のままでよい**。PR ブランチへ切り替えない |
| **E2E シナリオ実行** | 変更後の挙動を実際に確かめる | `../../review2/references/e2e-runbook.md` の判断表と明示承認が要る | PR の head |

**画面の取材は、E2E を実施しない PR でも行う。** 画面差分が 0 行でも、その設定を保存する画面や、
不正な値を送れないことを示す一覧の画面は撮れる。E2E が「不要」と判断されたことを、
取材をしない理由にしない。

E2E の実行判断・承認・環境準備・シナリオ表は `../../review2/references/e2e-runbook.md` に従う。
この文書は**撮り方だけ**を書く。

---

## 1. どのブラウザで撮るか

既定は **Aside（`mcp__aside__repl`、Playwright）**。独立したブラウザセッションを持つので、
ユーザーのタブやウィンドウを壊さない。

**Claude in Chrome（`mcp__claude-in-chrome__*`）へ切り替えるのは次の 2 つだけ**:
- ユーザーが「操作の様子を画面で見たい」と言ったとき（Aside のタブはユーザーの画面には出ない）
- ログイン済みの実ブラウザプロファイルが要るとき

どちらを使ったかは、E2E の証拠欄に明記する。

## 2. 撮り方

### 範囲を切って撮らない

`page.screenshot({clip})` も `Page.captureScreenshot` の `clip` も**位置がずれる**。
clip 無しでビューポート全体を撮り、ホスト側で切り出す。

```bash
sips --cropToHeightWidth <H> <W> --cropOffset <Y> <X> in.jpeg --out out.jpeg
```

### 保存先

`page.screenshot({path})` はセッションディレクトリ外を `escapes the session directory` で拒否する。
`display()` を使うとセッションの `tmp/repl-display-*.jpeg`（幅 2000px の JPEG）へ落ちるので、
そのファイルをホストから読んで加工する。

### 順序の注意

`page.screenshot()` を撮ると `setDeviceMetricsOverride` が外れる。
画面幅を固定して検証している最中は、**幅に依存する確認を全部終えてから**撮る。

### 要素単体を撮ろうとしない

`locator(...).screenshot()` は `Invalid parameters` で落ちる。
対象を `scrollIntoView` してから `page.screenshot()` を撮り、あとで切り出す。

## 3. 何を撮るか

### 3-1. 画面の取材（節 0.5 用・毎回）

図解の節 0.5 の**各ブロックに最低 1 枚**。何を撮るかの判断は `explainer-html.md` 第 3 章の表。

画面が変わらないブロックでは 1 枚でよい。撮る対象の見つけ方:

1. その処理を起動する操作はどの画面か（保存ボタンのある設定画面、アップロード画面、一覧の操作メニュー）
2. 「画面からは到達しない」と言いたいなら、**到達しないことが見える画面**を撮る
   （選択肢が一覧から選ばせる形になっている、入力欄が無い、権限で項目が消えている）
3. 変更後に増える表示があるなら、増える場所が分かるように変更前も撮って対にする

画面が変わらないブロックなら、PR ブランチを立てる必要は無い。現行の dev や localhost のままでよい。

### 3-1-2. 表示が変わるブロックの「変更後」

**変更後が本体で、変更前は比較用。** 変更前だけ撮って終わらせない。

変更後を撮るには PR のコードが動いている必要があるが、**メインの作業ツリーを切り替える前に、
切り替えずに済む手順がリポジトリにないかを先に見る**（Phase 0 の review profile に入っている。
PR のビルドを別ポートで出す、preview 環境を使う、隔離したコンテナで立てる、など）。
切り替えずに撮れるなら承認は要らない。

切り替えが要るなら、**撮るかどうかをユーザーへ 1 行で聞く**。聞き方は
「変更後を撮るには ◯◯ が要ります（所要 ◯分・影響 ◯◯）。撮りますか」。
E2E シナリオの実行とは別の話なので、E2E が「不要」でもこの 1 行は出す。

撮らない選択になったら、`figcaption` を「変更前のみ（変更後を撮るには ◯◯ が要る）」にする。

### 3-2. E2E の証拠（実行したときだけ）

`e2e-runbook.md` のシナリオ表（normal / boundary / permission / regression / co-mount / recovery）の
各行について、**変更前ブランチと変更後ブランチで同じ画面を 1 枚ずつ**撮って対にする。

- 対にできない場合（変更前には画面自体が無い等）は「変更後のみ」と明記する
- 差が見える範囲だけを切り出す。全画面のまま貼らない
- 数値が変わる変更なら、**数値が読める解像度**まで拡大して切り出す（この節の目的は数値の対比なので、
  読めないスクショは証拠にならない）

## 4. 埋め込み前の加工

- **重複を先に落とす。** 同じバイト列を 2 回埋めない。別の説明を付けたいなら、その説明が指す範囲へ
  切り出し直して別の画像にする。

```bash
md5 -q *.jpeg | sort | uniq -d   # 何か出たら、その 2 枚は切り出しをやり直す
```

- 長辺 1200px 以内へ縮小。1 枚 300KB を目安にする
- HTML 全体で 16MB 未満（`build-html.py validate` の上限）。超えたら**枚数を減らす**（品質ではなく枚数で削る）
- base64 へ変換して `data:image/jpeg;base64,...` として埋め込む

```bash
sips -Z 1200 in.jpeg --out small.jpeg
base64 -i small.jpeg | tr -d '\n' > small.b64
```

---

## 5. 撮ってはいけないもの

- 秘密情報・トークン・PII・実顧客名が写り込んだものは**採用しない**。マスクではなく撮り直す
- 本番環境の実データ。検証はローカルまたは dev の検証用データで行う
- ログイン画面へのパスワード入力の過程（Claude in Chrome ではパスワード入力自体を行わない。
  ログインはユーザーに頼む）
