# Design Tokens

意匠の値の正典は実装（`ts/packages/design-tokens/src/` と `ts/packages/ui/src/theme.css`）と、
それを守るテストである。写像版の読み物は `docs/design/design-language.md`、そう決めた理由の記録は
`.kiro/specs/ui-airbnb-foundation/design.md` の D1〜D8。以下は忘れると壊れる規律だけを置く。
実測値をここへ書き写さない。値は上の 2 箇所が持ち、機械照合が守っている。

## 色

- **ブランド色とアクション色を分ける。** ブランド色は白文字と WCAG AA（4.5:1）に届かないため
  装飾・アイコン・大テキスト専用であり、アクション面にも文字にも使わない。
- **hover は暗くする方向で作る。** `/80` のようなアルファ合成は白背景では合成後が明るくなり、
  ホバー時にだけ AA を割る（Issue #50）。各成分を定数倍した確定値をトークンへ置く。
- **成功色をアクション色と共有しない。** 共有していると、アクション色を暖色へ変えた瞬間に
  成功通知が危険通知と同系色になる。色相の変化は輝度を変えないので、比を見るガードは全緑で通る。
- **フォーカス輪郭にアクション色を参照しない。** 輪郭は本文色で描く。`outline-offset` を 0 にすると
  「隣接色は親の背景」という前提が崩れ、隣接コントラストの検証ごと組み直しになる。
- **`color-mix` は `in oklab` で書く。** `in oklch` は無彩色の色相が powerless になり赤へ解決される。
  混色を足したら `ts/packages/ui/test/color-mix-allowlist.json` へ実測値ごと登録する。

## スケール

- **`@theme` に余白の名前付きキーを宣言しない。** 宣言すると幅・最大幅・最小幅・フレックス基準幅の
  解決先が既定のコンテナ寸法スケールから余白スケールへ覆われ、画面が壊れたままビルドが通る
  （Issue #54）。CSS では `p-4` のような数値スケールで書き、トークン側の段は CSS を経由しない
  消費先（LINE Flex Message 等）へ値を渡すために持つ。
- **角丸の段を上書きしない。** 一部の段だけ変えると隣の段と同値になるか順序が逆転する。
  重複の検出は同値しか見ないため逆転は検出されない。段は既定のまま、役割の割当だけで意匠を表す。
- **段を足したら整合ガードのプローブへも足す。** Tailwind は参照されていないテーマ変数を出力しない。
  プローブへの追加を忘れると「生成 CSS に出ていない」という別の顔をした失敗になる。
- **影は 1 段だけ。** 面の分離は影ではなく輪郭と余白が担う。無印の `--shadow` は上書きしない
  （既定クラスと同名になり、意味が静かに変わる）。

## 部品

- **部品側で輪郭を打ち消さない。** フォーカス指標は `@layer base` に一本化してある。
  打ち消すユーティリティは `@layer utilities` に生成され、レイヤ順により詳細度と無関係に base へ勝つ。
- **生の色を書かない。** 直書き hex も既定パレットの色クラス（`bg-red-500` の類）も
  `scripts/check-design-tokens.sh` が落とす。色は必ず意味論トークン経由で指定する。
- **部品を足したら検証面へも足す。** `ts/apps/survey-web/src/app/ui-check/page.tsx` が
  部品ソースの唯一のコンパイル経路であり、載せない部品は型検査も実描画検証も受けない。

## 書くときの注意

- **Tailwind はソースをプレーンテキストとして走査する。** コメントに書いたクラス名や hex まで
  ユーティリティ生成とガード検出の対象になる。撤去したクラス名を literal で書き残さない。
- **トークンを変えたら先にビルドする。** `@fwlm/design-tokens` は dist 配布なので
  `pnpm -C ts --filter @fwlm/design-tokens build` を挟まないとテストが古い値を見る。
  このとき出る失敗メッセージは実際の原因と食い違う。
