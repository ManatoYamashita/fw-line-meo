# Implementation Plan

本計画は「**ガードを先に入れて赤化を実証してから是正する**」という本リポジトリの規律（要件 5.9）に従う。したがってタスク 2 で検証を追加して現状に対する赤化を確認し、タスク 3 で是正して緑へ転じさせる。**緑を先に見てはならない。**

変更の実体は `theme.css` から 8 行を除去することであり、重心は検証の側にある。新規の外部依存はゼロ。

`(P)` は直前の同階層タスクと同時実行できることを示す。新設ガードは単一のテストファイルを共有するため、検証タスクの多くは `(P)` にできない（各タスクの補足に理由を記す）。

  - 素の Tailwind のみを基準線としてコンパイルする手続きを追加する（プロジェクトのテーマを読み込まない）
  - 基準線が実際に素の Tailwind であることの自己確認を組み込む（既定のコンテナ寸法が現れること）
  - 観察可能な完了条件: 既存の統合検証が**全件緑のまま**共有モジュール経由で走り、基準線コンパイルが既定値を返す
  - _Requirements: 1.3, 5.7_

- [ ] 1.2 (P) スケール解析の純関数群を用意する

  - 越境衝突・角丸の段の重複・トークンとの役割対応の乖離を、それぞれ違反の一覧として返す純関数を用意する。例外を投げず、空配列で「違反なし」を表す
  - 副作用を持たせない。入力は CSS 文字列とトークン定義のみとし、ファイル読み書きやコンパイルを行わない（タスク 2.4 の注入対照が同じ判定関数を呼べるようにするため）

## Implementation Notes

- **[1.1 前提] `@fwlm/design-tokens` は dist 配布のため、新しい worktree では先にビルドが要る。** 未ビルドのまま `@fwlm/ui` のテストを走らせると `theme-sync.test.ts` と `contrast-usage.test.ts` が `Cannot find module '@fwlm/design-tokens'` 相当で 2 件失敗する（実装の欠陥ではない）。`pnpm -C ts --filter @fwlm/design-tokens run build` を先に実行する。ベースライン: ビルド後 **193 件緑**。
- **[1.1 実測・空振りの実例] 自己確認の照合先に `--color-brand` を選ぶと空振りする。** Tailwind は参照されないテーマ変数を出力しないため、`bg-brand` を使う部品が無い現状では `--color-brand` は**現行の生成 CSS にも現れない**。「基準線が theme.css を読み込んでいないこと」の照合先としては常に真になり、検出力ゼロの緑になる。実測で確認し `--color-primary`（Button の `bg-primary` により現行では必ず出力される）へ差し替えた。**本 spec が塞ごうとしている失敗様式を実装中に自ら踏んだ事例**であり、以降のプローブ選定でも「現行で実際に出力されるか」を必ず実測すること。
- **[1.1] `test/support/` は `test/` より 1 階層深い。** パッケージルートの解決は `resolve(dirname(fileURLToPath(import.meta.url)), '..', '..')`。切り出し時に階層を数え直さないと `APPS` のパスが全滅する。
- **[1.1 境界]** 基準線コンパイルの自己確認は `test/token-scales.test.ts`（TokenScalesGuard 境界）に置いた。未実行のコードは未検証のコードであり、1.1 の観察可能な完了条件「基準線コンパイルが既定値を返す」を恒久的に固定するため。タスク 2.1 以降が同ファイルを拡張する。

## 留意事項

- **押しボタン小寸法の角丸の到達値が変わる。** 要件 3.2（各段が相異なる）がある以上、現在の値を維持する選択肢は存在しない（維持すると押しボタンの段と隣の段が同値になり要件違反になる）。実測してタスク 5.1 の Implementation Notes に記録する。
- **`@fwlm/ui` の `test/` は型検査されていない。** 型検査の対象がソース配下のみで、既存テストは型エラーを 8 件抱えている（実測）。本 spec の Out of Boundary（#53 / #55 の領分）とし、タスク 2.4 の注入対照が判定の全分岐を実行時に踏むことで補償する。
- **要件 7 は文書の是正だが本 spec のスコープに含める。** Issue #54 が明示的にスコープへ含めており、除外すると要件カバレッジが欠ける。タスク生成規則の「文書タスクを除く」は配布物・営業資料を指すものと解する。
- 作業は worktree `feat/ui-token-collision` に隔離済み。Issue #57 が別 worktree で同じテーマ CSS の**色役割行**を編集中だが、本 spec は色に触れないため独立に成立する。
