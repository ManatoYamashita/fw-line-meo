N4-C は「判定の相手を親の背景とみなす前提」そのものを壊す変異である。前提が崩れたときに

### 実装で判明したこと（後続 spec への申し送り）

- **`@fwlm/design-tokens` は dist 配布なので、値を変えたら `pnpm --filter @fwlm/design-tokens build`
  を先に走らせないとテストが古い値を見る。** これを踏むと「theme.css に design-tokens が知らない色が
  混入している」という、実際とは違う失敗メッセージが出る
- **`docs/design/vendor/` は使えない。** `.gitignore` の `vendor/`（Go の依存ベンダリング用）が
  パス位置を問わず一致し、追跡対象から静かに外れる。`docs/design/upstream/` にした
- **原典の逐語コピーは既存の文書規約ガードとトークンガードを無改変で通った**ため、除外規則は
  入れていない。発火ゼロの除外はガードを弱めるだけで、守っている証拠にならない。
  上流の更新で通らなくなったときに初めて除外を足し、その時点で対照ケースを対にすること
- **見出しの太さと行間は、`app-integration.test.ts` の既存検査が一切見ていなかった**
  （`font-weight` は「数値であること」、`font-size` は「トークン参照であること」しか要求せず、
  `line-height` は無検査）。N2 はこの空白を埋めるものであり、**既存の検査が緑であることは
  一致の証拠になっていなかった**

### 目視確認（要件 1.2, 2.2, 2.4, 4.1・Chromium・検証面）

実測値はブラウザの `getComputedStyle` から読んだ。目視の印象だけで済ませていない。

| 確認項目 | 実測 | 判定 |
|---|---|---|
| アクション色と危険色が並んだとき CTA が「危険」に読まれないか | CTA は `rgb(224, 11, 65)` の不透明なベタ塗りに白文字、危険は淡い面に `rgb(179, 37, 5)` の濃い文字 | **混同しない。** 色相が近くても**描画形状が違う**ことが緩衝になっている（設計 D3 の想定どおり） |
| 成功通知が緑のままか | `rgb(21, 128, 61)`・role=status | **緑のまま。** アクション色の差し替えに巻き込まれていない（D2 が効いている証拠） |
| 危険通知が別色か | `rgb(179, 37, 5)`・role=alert | 成功と明確に別の色相 |
| 輪郭がインクで、アクション色で塗ったボタンの周囲でも見えるか | キーボードで到達した CTA で `outline: 2px solid rgb(34, 34, 34)` / `offset: 2px` / `:focus-visible` が真 | **見える。** 2px の隙間を挟んで黒い輪郭が明瞭に出る |
| 見出しの階層 | h1 = 24px / 700 / 行間 30px（1.25）、h2 = 20px / 600 / 行間 25px（1.25） | 設計 D7 のとおり。本文と区別できる |

**プログラム的な `focus()` では `:focus-visible` は立たない**（実測で `focus-visible=false`・輪郭も出ない）。
実キー入力の Tab で到達させて初めて立つ。目視確認をスクリプトで代替すると、
**輪郭が出ていないのに「出ている」と読む**ことになる。
