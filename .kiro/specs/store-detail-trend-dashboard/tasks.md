# Implementation Plan

> **実装順序の規律**:
> - 判断はまず正典へ書く（要件 9.1）。
> - 構造契約の検証は、実装を足す前に強める（要件 9.2）。
> - 各タスクの「観察可能な完了」に書いた赤・緑・件数が得られなければ、検証が対象へ接続していない。そのまま先へ進まない。
>
> **既知の地雷**（詳細は design.md「実装上の注意（既知の地雷）」）: どのタスクでも次を守る。
> - app コードに前置なしの `#265` を書かない（hex 色と誤検出される）。「Issue #265」と書く。
> - store-detail のテストとコメントを含めて、`bg-primary`・`bg-card`・`field-sizing-content`・`animate-spin`・`outline-none`・単独の語 `dark` を書かない。

> - `catch {}` を書かない。
> - 新しいファイルは `app/store/` か `lib/` に置く（`components/` を作ると lint の対象から外れる）。

- 部品テストの fixture の規律: 表示が 2 つの出どころ（例: 窓の終点と、値のある最後の日）のどちらからでも作れるなら、両者が食い違う fixture を最低 1 つ置く。代表の fixture が両者を一致させていると、取り違えの変異が緑のまま通る（3.1 で実測）。
- jsdom は、実装していない CSS プロパティ（paint-order など）を style 属性から黙って捨てる。インライン style の許可リストは、`react-dom/server` の `renderToStaticMarkup` の文字列でも照合する。

- 実装より先の赤は、フラグの無効側に HEAD の実装そのものを差し込んで取る（`git show HEAD:<file>` の中身を使う）。無効側を自前で書き直すと、再現した「以前の描画」がずれて、赤の結果が変わる（4.1 で実測）。
- 本物の index に触れていないことは、`git diff --cached --name-only` が空であることで確かめる。index ファイルのハッシュは、`git status` が stat キャッシュを書き戻すだけで変わる。
