# デザイン言語（fw-line-meo 写像版）

このプロジェクトの意匠が「何を、なぜ、どの値で」決めているかを 1 箇所にまとめた文書である。
面を実装する人とエージェントが実際に読むのはこの文書であり、参照デザインシステムの逐語コピー
（`docs/design/upstream/`）ではない。原典と我々の設計は 10 点以上で意図的に乖離している。

本文の数値は `ts/packages/ui/test/design-language-doc.test.ts` が実装値と両方向で照合する。
文書と実装がずれたまま CI が緑になることはない。

`attribution` だけは、値の決め手が意匠ではなく外部のポリシーにある。Places API は帰属表示の文字色を
白・黒・灰の 3 つの決め打ちの値に限り、本文色（`text`）はそのどれでもない。帰属表示に本文色を
継承させるとポリシーの外へ出る。白い面の上に置くので白は採れず、黒は本文より強く見えるため灰を採った。
許される 3 値そのものは `ts/packages/design-tokens/test/tokens.test.ts` が持ち、トークンの値が
その中にあることを機械検証している。

`googleSignIn*` の 3 役割も、値の決め手が外部の規定にある。Sign in with Google の branding guidelines は
ボタンの配色を Light・Dark・Neutral の 3 つに限り、G ロゴを規定外の背景へ置くことを禁じる。
アクション色（`primary`）の塗りにロゴを載せると違反になるので、ログインの主操作だけはこの 3 色で描く
（7.9 節）。塗りは `background` と同値だが、`background` を動かしたときにボタンまで動かないよう
役割を分けた。3 値は `ts/packages/design-tokens/test/tokens.test.ts` が規定の値と突き合わせている。

LINE Flex Message 用の色集合（`lineColors`）は本表に含めない。非 Web コンテンツであり
WCAG の検証対象外だからである。値は原則として現行の実装と同一に保ち、Web 面の意匠差し替えで
LINE の見た目が動かないようにする。**例外は Google Maps の帰属表示の色（`lineColors.attribution`）で、
現行の実装から採らず、Web 側と同じくポリシーが許す色から選んでいる。** 正典は
`ts/packages/design-tokens/src/colors.ts` にある。

### 2.3 採らなかった原典の色

いずれも閾値に届かないという理由で落としている。`測定条件` が `素` の行は白背景に対する比、
`` `/20` 面上 `` の行はその色を不透明度 0.2 で白へ合成した面の上に同色の文字を置いた比である。

| 原典の色 | 値 | 測定条件 | 実測 | 閾値 | 不採用の理由 |
|---|---|---|---|---|---|
| muted-soft | `#929292` | 素 | 3.112 | 4.5 | 無効リンク色という役割が現行に無く、無効表現は不透明度が担う |
| legal-link | `#428BFF` | 素 | 3.297 | 4.5 | リンク色はアクション色へ一本化する |
| border-strong | `#C1C1C1` | 素 | 1.800 | 3 | SC 1.4.11 の 3:1 に届かない。現行の識別用の枠色を維持する |
| primary-disabled | `#FFD1DA` | 素 | 1.365 | 4.5 | 無効化は WCAG の対象外であり、現行の不透明度で足りる |
| primary-error-text | `#C13515` | `/20` 面上 | 4.077 | 4.5 | 淡い面の上に同色の文字を載せる表現で AA を割る。エラー族の暗い方を採った |

`scrim` は覆い面の色でモーダルを導入していない現状には対応する役割が無い。
これらは数値ではなく役割の不在で落としているので、上の表には入れない。

### 2.4 色の構造規律

**ブランド色とアクション色を分ける。** ブランド色は白文字と 3.516:1 で AA に届かないため、
装飾・アイコン・大テキスト専用に降格してある。アクション面と文字にはアクション色を使う。

**hover は暗くする方向で作る。** `/80` のようなアルファ合成は白背景では合成後が明るくなり、
ホバーしたときにだけ AA を割る。各成分を定数倍した確定値をトークンとして持つ。

**成功色をアクション色と共有しない。** 共有していると、アクション色を暖色へ変えた瞬間に
成功通知が危険通知と同系色になる。これは色相の変化であって輝度の変化ではないため、
コントラスト比を見るどのガードにも掛からず CI が全緑のまま通る。

**フォーカス輪郭はアクション色を参照しない。** 輪郭の色は本文色であり、白面に対して 15.910:1 を持つ。
`outline-offset` を 0 にすると「隣接色は親の背景である」という推論が成立しなくなるため、
0 にする変更は輪郭の色の再検証を伴う。

## 3. 余白

原典の 9 段はいずれも Tailwind の数値スケール（基数 0.25rem）で余りなく表現できる。
これが「`@theme` に余白の名前付きキーを宣言しない」という規約を守ったまま原典の余白律を採れる根拠である。

| 出典の段 | 値 | 倍率 | クラス例 | px |
|---|---|---|---|---|
| `xxs` | `0.125rem` | ×0.5 | `p-0.5` | 2 |
| `xs` | `0.25rem` | ×1 | `p-1` | 4 |
| `sm` | `0.5rem` | ×2 | `p-2` | 8 |
| `md` | `0.75rem` | ×3 | `p-3` | 12 |
| `base` | `1rem` | ×4 | `p-4` | 16 |
| `lg` | `1.5rem` | ×6 | `p-6` | 24 |
| `xl` | `2rem` | ×8 | `p-8` | 32 |
| `xxl` | `3rem` | ×12 | `p-12` | 48 |
| `section` | `4rem` | ×16 | `p-16` | 64 |

**`@theme` へは宣言しない。** 名前付きキーを宣言すると、幅・最大幅・最小幅・フレックス基準幅の
解決先が既定のコンテナ寸法スケールから余白スケールへ覆われ、画面が壊れたままビルドが通る。
CSS では数値スケールで指定し、上の表は LINE Flex Message など CSS を経由しない消費先へ値を提供する。

意匠差し替えに伴い `md` の意味が `1rem` から `0.75rem` へ移り、`1rem` は新しいキー `base` になった。

## 4. 角丸

**スケールの段そのものを上書きしない。** 原典の形は既存の段への役割割当だけで表す。
一部の段だけを独自値へ上書きすると、上書きしなかった隣の段と同値になるか順序が逆転する。
重複の検出は同値しか見ないため、逆転は検出されないまま画面へ出る。

| 段 | 値 | クラス | 使用部品 | 出典の段 |
|---|---|---|---|---|
| `sm` | `0.25rem` | `rounded-sm` | （なし） | xs（4px・一致） |
| `md` | `0.375rem` | `rounded-md` | `button.tsx` | 対応段なし |
| `lg` | `0.5rem` | `rounded-lg` | `alert.tsx`, `button.tsx`, `field.tsx`, `input.tsx`, `select.tsx`, `textarea.tsx` | sm（8px・一致） |
| `xl` | `0.75rem` | `rounded-xl` | （なし） | 対応段なし |
| `2xl` | `1rem` | `rounded-2xl` | `alert-dialog.tsx`, `card.tsx`, `table.tsx` | md（14px・2px の差を受容） |
| `4xl` | `2rem` | `rounded-4xl` | `badge.tsx` | xl（32px・一致） |
| `full` | `9999px` | `rounded-full` | `radio-group.tsx` | full（一致） |

原典の lg（20px）に対応する段は置いていない。消費する部品が 1 つも無いためである。
`xl`（12px）も現在は消費先を持たない。カードが原典の md へ寄って `2xl` へ移ったためで、
段そのものは Tailwind 既定として残る（段を消すと既定クラスの意味が変わる）。

## 5. 影

| 段 | 値 | 用途 |
|---|---|---|
| `raised` | `0 0 0 1px #00000005, 0 2px 6px 0 #0000000A, 0 4px 8px 0 #0000001A` | 浮いた面。原典が持つ唯一の影の定義をそのまま採った |

**面の分離は影ではなく輪郭と余白が担う。** 原典は影を 1 つしか持たず、深さは写真と角丸の
クリッピングで表現する。この設計思想に倣い、カード相当の面は `ring-1` の輪郭で分離する。

**一覧表の端に出る捲れる手がかり（§7.18）は、この段に数えない。** 面を浮かせる表現ではなく、
容器の背景に本文色を薄めた濃淡を描くだけであり、独自の値のトークンも持たない。
濃さの根拠は §2.2 の該当行にある。

名前を無印にしないのは、無印が Tailwind 既定のユーティリティ名と同名になり、
上書きすると既定クラスの意味が静かに変わるためである。名前付きの段は加算的で曖昧さがない。

## 6. 見出し階層

素のタグに与える既定と、共通部品 `Heading` の既定は同じ段を指していなければならない。
同じ見出しレベルが、素のタグで書いたか部品で書いたかによって別の大きさで描かれるのを防ぐためである。

| タグ | サイズ段 | 実寸 | 太さ | 行間 | Heading の既定 |
|---|---|---|---|---|---|
| `h1` | `2xl` | `1.5rem` | 700 | 1.25 | `2xl` |
| `h2` | `xl` | `1.25rem` | 600 | 1.25 | `xl` |
| `h3` | `lg` | `1.125rem` | 600 | 1.375 | `lg` |
| `h4` | `base` | `1rem` | 600 | 1.375 | `base` |
| `h5` | `sm` | `0.875rem` | 600 | 1.5 | `sm` |
| `h6` | `xs` | `0.75rem` | 600 | 1.5 | `xs` |

行間の値は Tailwind の `leading-tight` / `leading-snug` / `leading-normal` と厳密に一致させてある。
原典の行間（1.18〜1.20）まで詰めないのは、日本語の全角字形が上下の余りを持たず、
折り返したときに窮屈になるためである。

文字サイズの段は次のとおりで、原典の 8px / 11px / 13px の段は採っていない（日本語字形で判読性に難がある）。

| 段 | 値 | クラス | px |
|---|---|---|---|
| `xs` | `0.75rem` | `text-xs` | 12 |
| `sm` | `0.875rem` | `text-sm` | 14 |
| `base` | `1rem` | `text-base` | 16 |
| `lg` | `1.125rem` | `text-lg` | 18 |
| `xl` | `1.25rem` | `text-xl` | 20 |
| `2xl` | `1.5rem` | `text-2xl` | 24 |

フォントはシステム日本語スタックを使う。原典のフォントは商用ライセンスであり、
原典が代替として挙げる書体は日本語字形を持たない。

```
system-ui, -apple-system, "Segoe UI", Roboto, "Hiragino Kaku Gothic ProN", "Hiragino Sans", Meiryo, sans-serif
```

**改行は文節の境目で行う。** 既定の改行は字の単位で折るので、「ログインし／てください」のように
語の途中で行が割れる。ルート要素の既定に `word-break: auto-phrase` を置き、日本語は文節の境目で
折り返す（`theme.css` の `@layer base`）。`word-break` は継承されるので、面の側にも部品の側にも書かない。
効くのは `lang="ja"` の文書だけで（Web 3 面の layout はすべて `<html lang="ja">`）、非対応のブラウザは
宣言を無視して従来の改行のまま描く。文節の判定は機械学習に拠り、意図しない位置で折ることがある。
そのときは文言の側で `<wbr>`（折ってよい位置）を足して直し、面の側で `word-break` を上書きしない。

**文節を割らないぶん、行の最小幅が広がる。** flex や grid の子は既定で中身の最小幅より縮まないので、
狭い画面で長い文節（長い表示名など）が行ごと面を押し広げる。押し広げた子には `min-w-0` を付けて縮める
（入れ子なら縮めたい段ごとに付ける。grid の子である行そのものにも要る）。縮めた箱に文節が入りきらない
ときに限り、ルート要素の `overflow-wrap: anywhere` が文節の途中で折る（非常時の折り返し）。
実例は店舗詳細の口コミの投稿者名の行で、320px 幅・200% 文字の E2E が検出した。

## 7. 面適用で共有する設計判断

**本節が各判断の正典である。** 後続 spec `ui-airbnb-surfaces` が作られたら、その design.md は
本節へリンクし、結論も数値も転記しない。転記は必ず古びる。由来欄が Issue を指している項目は、
spec 側に審議の記録ができた時点で由来欄だけを差し替え、結論の本文はここから動かさない。

### 7.1 星は ink で描く

**星評価は本文色で描く。** 原典が星をインクで描き黄色や琥珀を使わないのはブランド判断であり、
黄色い星は旅行文脈で安っぽく見えるという理由が原典自身に明記されている。加えて、
意匠差し替え後のアクション色は赤であり、満足度評価が赤い星になる。琥珀色は生パレット色クラスとして
`scripts/check-design-tokens.sh` が落とす。未選択は補足色、選択済みは本文色で追加トークンはゼロ。
罫線色を未選択に使わないのは、罫線色が純装飾として定義された色であり、状態を伝える字形の色には
足りないためである。識別用の枠色も変数参照専用であり、文字色のユーティリティとしては使わない。
アフォーダンスはタップ領域と字形差と必須表示で補償する。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)（未選択の色の訂正は
`.kiro/specs/ui-airbnb-surfaces/design.md` の「第 0 段階: 正典の追記」）

### 7.2 テーブルは表のまま装飾する

**行・列・セルの支援技術上の役割を保ったまま意匠を適用し、カードリスト化しない。**
容器の側がカード化を担い、面の分離は輪郭で表す。セル余白は原典の 16px、見出し行はやや詰める。
行区切りは 1px の罫線のみで、縞模様は使わない（原典は一切使わない）。
行の重畳時の面塗りは付けない。行自体が押せないため、誤った可動感を与えるからである。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)

### 7.3 巨大表示の寸法は暫定である

**巨大な数値表示は store-detail の順位数値に置き、§6 の文字サイズの最大段（`text-2xl`・`1.5rem`）で描く。**
原典が「システム唯一の大声」と呼ぶものをプロダクト全体を通して守るための表示だが、その意図が
求める大きさに足る段は文字サイズのスケールに存在しない。段を足すのはトークン層の変更であり、
面へ意匠を当てる作業の境界を超えるため、暫定として最大段で代用する。

**この段は主見出しと同じ寸法である。** したがって「プロダクト全体で 1 箇所」という一意性は、
暫定の間は寸法では表せない。ここでは一意性を主張しない。足りる段が入った時点で本文の寸法と
面の実装を差し替え、そのときに一意性の主張を復活させる。段の追加は
[#185](https://github.com/ManatoYamashita/fw-line-meo/issues/185) で追う。
客向けアンケートでは集計値を見せる対象が無いため、この表示を置かない。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)（暫定の寸法は
`.kiro/specs/ui-airbnb-surfaces/design.md` の「第 0 段階: 正典の追記」）

### 7.4 ブランド色は 1 画面 1〜2 箇所まで

**ブランド色の使用は top-nav と login のワードマークに限る。**
原典の構成は「白 90% とインク、そこへアクセントを 1〜2 箇所」であり、原典自身もワードマークだけが
ブランド色である。装飾専用トークンの唯一の正しい使い所がここになる。

**ワードマークは、アイコン・アプリ名・面の役割の 3 つで組む**（`ts/apps/dashboard-web/src/components/wordmark.tsx`）。
2 段に組み、上の段にアプリ名を補足の色の 12px で、下の段に面の役割（「管理用ダッシュボード」）をブランド色の
20px の太字で置く。20px の太字は大きい文字の閾値（14pt の太字）を越える。アプリ名は 3 アプリで共通なので、
この画面で目に入れたいのは面の役割のほうである。アプリ名を大きく置いた版（2026-09-26）は帯の横幅を取りすぎ、
案内リンクと近づいた。ブランド色は大きい文字にしか使えないので、小さくしたアプリ名には載せない。
アプリ名は語の切れ目でだけ折れる。表示名は 3 アプリとも「Firstweb 集客AIアシスタント」＋
画面の役割で揃える（OAuth 同意画面のアプリ名は「集客AIアシスタント」のまま）。アイコンは名前と同じことを言う装飾なので読み上げない。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)

### 7.5 overlay 系は操作結果の Toast だけを例外とする

**Dialog / Popover / Tooltip / Tabs は 4 面すべてで新規ベンダリングしない。** Select は標準要素を
共通部品で包む。管理ダッシュボードだけは、非同期操作の成功・失敗を画面遷移後も見失わせないため、
`Sonner` の Toast を共通の通知面として使う。Toaster はルートに 1 つだけ置き、通知には利用者が
理解できる結果と次の行動だけを記す。API・SDK・例外の内部メッセージをそのまま表示してはならない。
各操作は Toast とは別に、実行中の押しボタンへ Spinner または処理中の文言を示し、重複実行を止める。
Toast の状態色は検証済みの意味色へ接続し、狭い画面では左右余白を含めて表示幅に収める。

**Toast は白い面に本文色の文字で描き、状態は左上の角から左辺に沿うにじみとアイコンの意味色で示す。**
成功は緑（`--success`）、失敗は赤（`--destructive`）の放射状のにじみを、左上の角から文字の手前まで
（幅 4rem・高さは Toast いっぱい）置き、アイコンはその内側に収める。
文字は状態を問わず本文色にする。状態を色だけに頼らず、アイコンの形と文言でも示す。
**出る場所は、帯が 1 段になる広い画面（1024px 以上）では右上、狭い画面では右下にする。** 狭い画面の帯は
3 段で、上に出すと Toast がロール・ログアウト・案内リンクを覆い、表示中はそれらを押せない（E2E の R2 で
実測）。600px 以下では Sonner が Toast を表示幅いっぱいに広げる。
**にじみは Toast の背景にも疑似要素にも描かない。** 文字の祖先の背景にグラデーションを敷くと axe は
対比を「判定不能（bgGradient）」へ、疑似要素に塗りを持たせると「判定不能（pseudoContent）」へ降ろし、
違反 0 件のまま Toast の文字の監査が消える（どちらも実測）。にじみはアイコンに添えた本物の要素で描き、
Toast の左の内側余白を広げて文字と重ねない。重なりの有無は E2E（dashboard-surfaces）が実寸で測る。

QR の行直下パネル・利用者編集の行直下パネル・停止確認のダイアログという既存の情報構造は
Toast へ置き換えない。Toast は操作結果の通知だけを担い、入力に結び付く検証エラーや、利用者が
次の行動を取るまで残す必要がある案内は従来どおり画面内にも置く。

由来: `.kiro/specs/ui-airbnb-foundation/design.md` の D6、Issue #342

### 7.6 写真前提の意匠は採らない

**写真プレートを前提にしたカードは真似しない。** 店舗検索の応答に写真は含まれず、
写真前提のカードを写真なしで真似ると空の灰色矩形が並ぶだけで劣化する。
借りるのは「タイトル・補足・右端の指示子」というメタの積み方だけにする。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)

### 7.7 前日比は色ではなく矢印

**増減は上下の矢印で示し、色で示さない。** 緑を上昇・赤を下降に割り当てると新しいトークンを
要求することになり、暖色一色のパレットとも衝突する。

### 7.8 帯の段組みと現在地の示し方

**管理ダッシュボードの帯は、広い画面（`lg` 以上）では 1 段に組み、高さを `h-20` に固定する。**
原典の `top-nav` の高さ（80px）と一致する。名前付きキーを宣言せず数値スケール（基数 0.25rem・§3）で
指定するため、余白の段を増やさずに解決する。

**狭い画面では 3 段に組み、案内リンクを折り返して全部見せる。** 1 段目はワードマークだけ（全幅）、
2 段目の右にロールとログアウト、3 段目に案内リンクを置く。ワードマークがアプリ名と面の役割を持つ長さに
なったため、ロール・ログアウトと同じ段では 320px の幅で重なった（2026-09-23 に実測。重なりは E2E の
R2 が要素どうしの箱の交差で検出する）。原典は狭い画面で帯をロゴと開閉の押しボタンへ畳み、リンクを
覆い面へ移すが、これは採らない。覆い面は §7.5 が使わないと定めたものであり、開閉の押しボタンは
帯の操作の個数（§8 の構造契約）を増やし、開閉には状態が要る。リンクを 1 行に並べたまま横に
捲らせる形も採らない。捲れる手がかりの無い帯では、画面の外のリンクが存在しないように見えた
（[#283](https://github.com/ManatoYamashita/fw-line-meo/issues/283)）。

**狭い画面では高さを固定しない。** 案内リンクの段の行数が、画面の幅とロールで変わるためである。左右の
余白は版面の外枠と揃え、ワードマークの左端を主見出しの左端に合わせる。段の間と 1 段目の上には、
ログアウトの押しボタンが外側へ広げる見えない操作領域が、案内リンクにも帯の外にも掛からない間隔を取る。

**段組みを切り替える境目を `lg` に置くのは、1 段の帯へ運営の案内リンクを全部並べるには
`md` の幅では足りないためである。** 字幅の実測から導いた任意の境目は、文言や書体が変わるたびに
古びる。段の上限を決めるのは常にリンクの語数であり、画素ではない。

**DOM の順は段組みで変えない。** ワードマーク・案内リンク・ロール・ログアウトの順であり、1 段の
帯では見た目の順と一致する。狭い画面ではロールとログアウトが案内リンクより上に見えるが、読み上げと
焦点の移動では案内リンクが先に来る。案内リンクの並びの内側の順は見た目と一致し、どの要素にも
到達でき、ブランド・行き先・身元と退出という意味の順も保たれるので、意味と操作性を保つ順として
扱う（WCAG 1.3.2・2.4.3）。見た目に合わせて DOM を並べ替えると、広い画面の帯で同じずれが
逆向きに生じる。

**現在地は下線の罫で示し、リンクの色は変えない。** 原典も現在地を下線で示す。色を併用しないのは、
帯のリンクへ色を足すと、面の側に置く色の閉じた集合（実効コントラストは §2.2 の該当行にある）が
広がるためである。色に依存しない示し方であることは、
状態の区別を色だけに委ねないという要求もそのまま満たす。支援技術へは現在地のリンクへ
`aria-current="page"` を与えて伝える。下線とこの属性は同じ判定から出し、片方だけが付く状態を作らない。
案内リンクの段でリンクが折り返すときは、折り返した行の間を、下線とそのリンク自身の文字との間より広く取り、
下線がどの行に属するかを近さで読めるようにする。
由来: `.kiro/specs/ui-airbnb-surfaces/design.md` の「第 0 段階: 正典の追記」（段組みは
[#283](https://github.com/ManatoYamashita/fw-line-meo/issues/283)）

### 7.9 ログインは本文系の版面で主操作を全幅にする

**ログイン画面は外枠の部品が持つ本文系（狭い方）の版面を使い、主操作の押しボタンを版面いっぱいに広げる。**
この画面は帯を持たず（未認証のときは帯を描かない）、操作は Google ログインだけである。
一覧系の広い版面を使うと、中央に小さな操作がひとつ浮くだけの画面になる。押しボタンの幅を
内容に合わせないのも同じ理由で、画面で唯一の操作が押しどころの小さい部品になるのを避ける。

**主操作は「Google でログイン」ボタンの規定に従い、アクション色で塗らない。** Sign in with Google の
branding guidelines は G ロゴを規定外の背景へ置くことを禁じ、配色を 3 つに限る。ここでは Light
（`googleSignIn*` の 3 役割・2.1 節）を採り、左に公式素材の G ロゴを 20px で置く（規定の本文に大きさの記載は無く、公式素材の 40px のボタンの中でロゴが占める寸法に合わせた）。ロゴは装飾なので読み上げない
（読み上げ名は「Google でログイン」のまま）。素材は公式の配布物（`signin-assets.zip`）の Web 用・Light・
文字なしの PNG から、ボタンの枠の内側だけを切り出したもので、ロゴ自体には手を加えていない。
**書体だけは規定（Google Sans Medium）に合わせていない。** Web 面の書体は 1 種類に保つ判断を優先した。

**主見出しと案内文は見出し周りの部品（`PageHeader`）で描き、案内文を通知の部品に入れない。**
案内文は画面の説明であり、状態の変化を知らせる通知ではない。通知の部品で描くと、枠のある箱が
入力欄のように見え、変化しない文言が読み上げ領域に載る。通知の部品を使うのは、利用資格が無いときの
危険の案内だけである。

**版面の段は増やさない。** 増やすと「どれを選ぶか」の判断が面ごとに発生し、
外枠を部品にした目的（意匠のドリフト防止）がそのまま失われる。
由来: `.kiro/specs/ui-airbnb-surfaces/design.md` の「第 0 段階: 正典の追記」

### 7.10 主操作の寸法区分は面の種別で決める

**ページの主操作は、管理面では部品の既定の寸法区分を、客向け面では拡大の区分を使い、
いずれも版面いっぱいに広げる。** 寸法の実値はここに書かない。部品の `size` 区分が持っており、
転記すれば必ず古びる。

区分を面の種別で分けるのは、客向けの主動線が QR からモバイルであり、利用者が IT に不慣れである
ことが前提だからである（steering `product.md`）。この面では押し損ねがそのまま離脱になる。
管理面は同じ操作を毎日繰り返す利用者が使い、1 画面あたりの操作の数も多いため、既定の区分で
密度を保つ。7.9 が主操作を全幅にすると定めたのは面の種別によらないので、そこは分けない。

**面の側で高さ・内側余白・文字寸法を書かない。** 書いた時点でその面だけが区分の外へ出る。
区分で足りないときは、面の都合ではなく区分の側の課題として切り出す。

**操作領域をラベルの行との合算で満たす構成では、その行の内側に反応しない帯を作らない。**
ラベルを制御の上へ積むと、2 つのあいだに、どちらにも属さない余白が挟まる。押しても何も起きない帯を
挟んだまま高さを足し合わせても、それは連続した 1 つの的の大きさではない。余白は見た目のために残し、
ラベルの側がその帯まで反応するようにする。ラベルが制御を包む構成は、行そのものが 1 つの的なので
この限りではない。合算で満たすと決めた以上、満たしているかどうかは行の外接矩形の大きさではなく、
その行のどこを指しても部品が反応するかで確かめる。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)
（行の内側の帯は [#286](https://github.com/ManatoYamashita/fw-line-meo/issues/286) の項目 4。
審議の記録は `.kiro/specs/ui-a11y-gaps/requirements.md` 要件 4.7 の 2026-09-19 の注記）

### 7.11 状態変化は色だけを 150ms で遷移させる

**状態を示す色は 150ms で遷移させ、遷移させる性質を名指しする。**
まとめて指定すると、後から足した性質が意図せず遷移の対象になる。色以外を遷移させないのは、
寸法や位置が動くと状態の変化ではなく画面の移動として読まれるためである。

**押下の表現に縮小を使わない。** 押下時の沈み込みは既に押しボタンの部品が持っており、
`theme.css` の動き低減の節はこれを「動きの経過ではなく到達状態」として、
動きの低減が要求されている環境でも保つと定めている。縮小を重ねると同じ役割が 2 通りになり、
一方だけが抑制の対象になる。

**面の側にも部品の側にも、動き低減の打ち消しを書かない。** 抑制は `theme.css` の `@layer base` が
全面へ一括で効かせている。重ねて書くと二重管理になり、片方だけ古びても誰も検出できない。
由来: [#41](https://github.com/ManatoYamashita/fw-line-meo/issues/41)

### 7.12 LINE 面の意匠は Web 面と別の律で決める

**配色は凍結し、我々が決めるのは余白・階層・区切りだけである。** LINE Flex は LINE アプリ自身の
UI の中に置かれるため、Web 面の意匠差し替えに追随させると周囲と衝突する。寸法の値も LINE 独自の
キーワードであり、CSS の数値スケールへ写像できない。したがって LINE 用のトークンが共有するのは
値ではなく役割であり、その正典は `ts/packages/design-tokens/src/line-layout.ts` にある。

**例外は Google Maps の帰属表示の大きさ（`attributionSize`）ただ 1 つで、ピクセル値を持つ。**
値の所有者が LINE ではなく Places API のポリシーだからである。ポリシーはテキストの帰属表示の
大きさを sp の範囲で定めており、キーワードでは実 px が分からず、その範囲に入るかを確かめられない。
由来: [#42](https://github.com/ManatoYamashita/fw-line-meo/issues/42)
由来: [#256](https://github.com/ManatoYamashita/fw-line-meo/issues/256)

### 7.13 LINE の巨大表示もプロダクト全体で 1 箇所

**競合店との比較レポートの順位数値だけが最大の段を持つ。** §7.3 の LINE 面への写像である。
折り返しを持たない文字は容器の幅を超えると省略記号で切り詰められるため、段を上げるときは
自動縮小の指定を対で添える。上げるだけでは劣化になる。
置き場は日次カードにあったが、カードの撤去に伴って比較レポートへ移した（Issue #256）。
プロダクト全体で 1 箇所という規律は変わらない。
由来: [#42](https://github.com/ManatoYamashita/fw-line-meo/issues/42)
由来: [#256](https://github.com/ManatoYamashita/fw-line-meo/issues/256)

### 7.14 バブルの内側余白は 1 つの規則で表す

**バブルの大きさに依らず、header・body・footer は同じ内側余白を宣言する。**
バブルごとに変えると、次に触る人が守れる規則にならない。群として読ませる間隔は、
セクションの内側を外側より詰め、節を閉じる区切り線はそれより広く取る。この 3 つの大小関係が
崩れると、面が 1 枚の壁に見えるか、区切り線が節を閉じないかのどちらかになる。
由来: [#42](https://github.com/ManatoYamashita/fw-line-meo/issues/42)

### 7.15 LINE 面では緑は押せるものだけが持つ

**アクション色と同値の緑を静的な文字に当てない。** LINE のアクション色は見出し用の緑と同値であり、
成功を表す淡緑の面の上では読みづらいうえ、同じバブルの操作と同色になって、押せない見出しが
押せるように読まれる。祝祭の面であることは面の背景色と主見出しの段が担う。

### 7.16 LINE のテキスト案内の書き方

**絵文字は完了の 1 箇所だけに置き、案内・催促・エラーには使わない。** テキストメッセージは
1 文 1 行で 3 行以内に収める。`**` による強調を書かない。LINE は Markdown を解さないため記号が
そのまま表示されるうえ、`scripts/check-markdown-emphasis.sh` は Markdown ファイルしか走査しないので、
TypeScript の文字列リテラルに書いた記号は機械検出されない。テキスト案内の Flex 化は行わない。

**例外は Google Places 由来のデータを載せるものである。** 変化があった日の通知は 1〜2 文の
短文だが、テキストメッセージではなく Flex で送る（Issue #256）。Places API のポリシーが
帰属表示の大きさと色を定めており、テキストメッセージにはその 2 つを指定する手立てが無いためである。
この例外は「Places 由来のデータを含むかどうか」だけで決まり、案内・催促・エラーの
テキストメッセージを Flex にしてよいという意味ではない。

### 7.17 店舗詳細は文章の列ではなく指標のダッシュボードとして組む

**順位・評価・クチコミ数・新着件数は、ラベルと値を分けた指標として描く。**
1 つの文章へ数値を連結すると、利用者は毎朝同じ文を読み解いてから昨日との差を探すことになる。
店舗詳細は日次確認の面なので、順位を最初の大きな値、評価とクチコミ数を次の指標群、新着を
独立した一覧として配置する。値の集合には `dl` / `dt` / `dd` を使い、視覚上の分離と
支援技術上の対応関係を同じ DOM から導く。

**競合は店舗ごとの比較行とし、店名の下に評価・クチコミ数・星差を同じ順序で並べる。**
店舗ごとに文章を組み立てない。長い店名は折り返し、数値は等幅数字で揃える。行そのものは
操作できないため hover 面は持たず、行の境界は一覧の区切り線だけで示す。

**推移の表の前に、表示期間の始点と終点から求めた要約を置く。**
順位と評価は `始点 → 終点`、クチコミ数は差分で示し、変化を表の全行から探さなくてもよい状態にする。
表は日別の一次情報として残し、列・行・セルの意味論と横方向の捲りを維持する。要約は既存データから
表示時に算出し、API や保存形式を増やさない。狭い画面で日付や短い列名を過剰に折り返さず、
通常の携帯幅ではセルの横余白を詰めて全列を見せ、文字拡大などでなお収まらないときだけ、
外側の焦点可能な容器で横へ捲れるようにする。
始点と終点にどの日を使うか、その日が公称の期間と食い違うときに何を添えるかは §7.19 が定める。

由来: [#258](https://github.com/ManatoYamashita/fw-line-meo/issues/258)

### 7.18 一覧表を狭い画面で読めるように保つ

**列の折り返しは、中身の種類ごとに表の部品が持つ語彙から選ぶ。** 語として分けて読むと意味が
崩れる短い値（ロールや状態のようなラベル、コード、日時）は折り返さない。区切りを持たない長い語
（メールアドレス）はどこでも折り返せるようにする。自由記述（店名・代理店名・表示名）は語の区切りで
折り返し、1 行に数語が並ぶ幅を保つ。語彙と、自由記述に保つ幅の実値は表の部品が持ち、面の側は
列ごとに語彙を選ぶだけで、幅も折り返しの指定も書かない（§7.10 と同じ理由）。列見出しは常に
折り返さない（部品の既定）。

**日本語はどの文字の間でも折り返せるので、規則を持たない列は、表が容器より広いとき 1 文字の幅まで
細る。** 折り返さない列だけを決めると、残りの自由記述の列がさらに細るので、2 つの規則は対で当てる。
§7.17 の推移表は表全体へ最小の幅を与えて列の詰まりを防いでいるが、自由記述を持つ一覧表では
その形を採らない。余った幅の配り方は描画エンジンと他の列の中身で変わり、中身の短い自由記述の列を
守れないためである。

**表が見える幅に収まらないときは、容器の端に濃淡を出して捲れることを示す。** 濃淡は、まだ捲れる側の
端にだけ出て、捲り切ると消える。容器の背景の重ね方だけで描き、状態も副作用も持たない。これは面を
浮かせる影ではないので §5 の段には数えない。濃さの上限は、表の文字がその最も濃い点に重なっても
AA を保つことであり、実値は §2.2 の該当行にある。濃淡は捲れることの唯一の手がかりではない
（容器は名前を持つ領域として焦点を得られ、列は途中で切れて見える）。したがって非テキストの
コントラストの対象としては扱わず、濃さは重なる文字の側から決める。

**短い値だけの表は、狭い容器でセルの横余白を詰め、文字や列を削らずに収める。** 密度の選択と実値は
表の部品が持ち、面は `responsive` の語彙だけを選ぶ。通常の 320px 幅では全列と末尾の桁まで見せる。
端末側で文字を拡大して収まらなくなったときは列を縮め続けず、上の横捲りへ退避する。ページ全体は
横へ溢れさせない。これにより「常に捲れる表」と「末尾を切って捲れない表」の両方を避ける。

**先頭の列は固定しない。** 固定した列は背景を塗る必要があり、容器の背景に描く濃淡を覆う。狭い画面
では見える幅をさらに削り、行の直下に挿すパネルとも重なる。

**行の直下に挿すパネルは、容器の見えている幅に留める。** パネルは全列にまたがるので、表が容器より
広いと見えている幅を超え、捲り位置しだいで操作が見えない所へ出る（WCAG 2.4.7・1.4.10）。留める
位置と幅はセルの左右の余白と結び付いているので、3 つとも表の部品が 1 つのファイルで持つ。印刷では
この包みを外す。
由来: [#283](https://github.com/ManatoYamashita/fw-line-meo/issues/283)（行の直下に挿すパネルは
[#259](https://github.com/ManatoYamashita/fw-line-meo/issues/259)）

### 7.19 店舗詳細の推移はグラフと表を同じ期間から描く

**グラフ・期間の要約・推移の表・現在値は、ひとつの窓から導く。**
窓は、推移の最新の記録日を終点とし、終点を含めて選んだ期間の日数だけ暦日を遡った範囲とする。
グラフの横軸はこの範囲の最初の暦日から終点までに固定し、記録の無い日は空白のまま見せる。期間の要約の
始点と終点には、指標ごとに、窓の中で値が記録されている最初と最後の日を使う。節の見出しと表の名前に入る期間も、
同じ窓から取る。表示ごとに期間を切り出すと境界の計算が重複し、どれかだけがずれた状態を、利用者は
食い違った数字として読む。終点に今日の日付は使わない。日次の取得が止まった日は古い終点のまま
表示されるので、現在値にはその値が記録された日付を添える。

**期間の要約の 3 組には、公称の窓と食い違う組にだけ、値を読んだ最初と最後の日を添える。**
節の見出しと図の題が名乗るのは公称の窓だが、3 組が読んでいるのは、指標ごとに値が記録されている最初と
最後の日である。記録が窓の日数に満たない店では、この 2 つは必ずずれる。ずれは、選んだ指標のグラフでは
線が窓の一部にしか伸びないことで見えるが、同時に並ぶ残りの組には手掛かりが無く、名乗った期間ぶんの
変化として読まれる。添えるかどうかは組ごとに独立に決める。3 組がそろってずれる日もあれば、終点の記録が
欠けた指標だけがずれる日もあるためである。一致する組には何も添えない。常に添えると、それが食い違いの
印であることが失われる。値が 1 件も記録されていない組は、読んだ日そのものが無いので記号のままにする。
日付は値と同じ組の中へ、値の後ろに置く。組の外や見出しへ出すと、指標ごとに違う期間を 1 つの文が名乗る
ことになり、読み上げでも値と結び付かない。書式は図の期間と同じ短い日付にし、値を読んだ日が 1 日しか
無い組には、その 1 日だけを書く。

**要約の値・両端の日・期間注記は、`summarizeWindow` が 1 つの値として返す。** 注記だけを
`(window, ends)` の別関数で後から求める形にすると、別の窓の端を型が受け入れ、値と注記の期間が
食い違いうる。呼び出し側は要約が持つ注記を描くだけにし、窓との比較を繰り返さない。

**LINE の 7 日レポートと LIFF の期間注記は、同じ事実を別の役割で示す。** LINE は公称の 7 暦日を
表で列挙し、データなし・取得失敗の日も明示する。その上の要約は取得できた最初と最後の日を常に先頭へ
置き、どの行から変化を測ったかを示す。LIFF は見出し・図・表が公称の窓をすでに示すため、同じ期間を
3 組へ常時重ねず、指標の両端が公称の窓と食い違う組だけに注記する。この差は表示条件の不統一ではなく、
欠測を列挙する LINE と、複数の指標要約を並べる LIFF の情報構造の差である。

**推移のグラフは自店の系列だけで描き、面の側に置く色を閉じた集合に限る。**
競合の推移を重ねると系列を色で見分けることになり、新しい色トークンを要求する。自店だけなら、
区別のための色の組み合わせが要らない。面の側に置く色は §7.8 の閉じた集合に倣い、本文色・区切り線色・
カードの地色・補助文字色に限る。線と点と最新値は本文色、罫線は区切り線色、端点の輪はカードの地色、
目盛りと日付は補助文字色で描く。最新値の文字は、線が後ろを通っても読めるよう、カードの地色の縁取りを
敷いてから本文色で塗る。文字と線の実効コントラストは §2.2 の該当行にある。
罫線は純装飾であり（§2.1）、値は目盛りの文字と推移の表で読む。
店舗詳細の面で色を書くのは、グラフの部品と Google Maps の帰属表示の 2 つだけとする
（検索欄・件数の文言・選択肢の札には色を書かない）。
検索欄・件数の文言・選択肢の札の色は、部品の側がトークンから解決するか、本文色を継承する。
ページ全体の地色と本文色はルートのレイアウトが与えるもので、面の側の色には数えない。

**帰属表示の色を面の側が書くのは、値の決め手が意匠ではなく外部のポリシーにあるからである。**
Places API は帰属表示の文字色を 3 値に限り、本文色はそのどれでもない（§2.1 の `attribution` の行）。
継承させると、本文色を動かした瞬間に帰属表示がポリシーの外へ出る。面が書くのは帰属表示のその 1 行だけで、
大きさもポリシーの範囲に収める。クラスの集合は `ts/apps/store-detail/test/store-page.test.tsx` が
完全一致で固定し、例外がそれ以上広がらないようにする。

**期間・指標・検索の操作は、取得済みのデータの見え方を変えるだけにする。**
操作はサーバーへの書込も再取得もせず、端末の保存領域・クッキー・閲覧履歴・画面の URL も変えない。
開き直すと既定の表示に戻る。閲覧専用という約束（competitive-daily-summary の要件 4.2）が禁じているのは
書込であり、表示の切替ではない。書込を不可能にしている担保は DB の権限と GET だけの経路にあり、
面の側はそれを、入力を受け付ける要素の許可リストで補う（§8）。

**期間と指標の選択肢は Field 構成の札で組み、検索欄とともに Card の外に置く。**
札は、ラベルの中に横向きの Field を置き、その中にラジオと題を並べる形にする。§7.5 がタブと overlay 系の
選択部品を使わないと定め、§8 の構造契約が押しボタンと選択欄を許さないので、排他の選択肢は常に見える
ラジオで示す。
操作領域の大きさ（§7.10）は部品の側が持ち、選択状態は色だけでなく、部品の側が持つ印の形と枠でも示す。
期間の群を先に、指標の群を後に置く。期間は下にある表示のすべてに効き、指標はグラフだけに効くため
である。操作をカードの中に置くと、効く範囲がそのカードの中だけに見える。競合の検索欄も一覧の Card の
外に置く。該当する競合がいなくなると一覧の Card は空状態に置き換わるので、中に置くと検索欄ごと
消えるためである。検索欄には、縦に積む Field で見えるラベルを付ける。

**縦軸は指標ごとに持ち、二重軸を作らない。ツールチップは使わない。**
順位・評価・クチコミ数は尺度が異なり、ひとつの軸へ重ねると、ある指標の変化を別の指標の目盛りで
読むことになる。順位は上ほど上位に描き、その向きをグラフの題に文言で添える。評価は星の取りうる
範囲の外へ広げず、小さな変化が縦幅いっぱいに誇張されない幅を保つ。クチコミ数の目盛りは整数にする。
ツールチップ（ポインタを重ねたときだけ現れる浮遊表示）を使わないのは、§7.5 が Tooltip を使わないと
定めているうえ、店舗詳細を開く LINE 内ブラウザにはポインタを重ねる操作が無いためである。日ごとの値は
直下の推移の表で読み、最新の値だけを点のそばに文字で添える。図形は表示幅に合わせて伸縮させ、目盛り・
日付・最新値の文字は §6 の段のまま描いて、表示幅によって縮めない。グラフの中には焦点を受け取る要素を
置かない。

**操作は、それが効く対象のすぐ上に置き、余白で塊を分ける。**
グラフは要約の 3 組より**上**、選択肢のすぐ下に置く。指標の札が効く先はグラフだけなので、間に指標が
効かない 3 組を挟むと、押した結果が画面のずっと下に出る。要約は「表の前」のまま、グラフの下に残る。
節は、見出しとその節の表示を選ぶ操作を近い間隔で束ね、束と結果の間をその 2 倍以上空ける（実値は §3 の
段で、束の内側 `gap-2`・束の間 `gap-6`）。操作の塊の内側と、塊と結果の間が同値だと、どこまでが 1 つの
塊かが余白から読めない。

**選択の結果は、読み上げ領域へも届ける。**
指標の札が効く先はグラフだけであり、グラフは図の名前でしか内容を持たない。名前は読み上げ領域ではない
ので、領域を 1 つ置かないと切替が読み上げ利用者に何も届かない。領域は窓がある限り同じ要素として留め、
文字だけを書き換える（要素ごと差し替わると通知が安定しない）。空の案内そのものを読み上げ領域にしない
のも同じ理由である。

**表示するものが無い状態は、すべて同じ空状態の部品で描く。**
「一覧が空」だけでなく、選んだ指標の値が期間内に 1 件も無いときも同じ部品で描き、描画領域と同じ高さの
下限を与える。素の段落で描くと、同じ役割が 1 つの面の中で 2 通りになり、切替のたびに面が大きく崩れる。
文言には窓の期間を入れる（この分岐は図の見出しごと落ちるので、期間が画面から消える）。

**並べるためだけの箱に役割を名乗らせない。**
札と検索欄の組み立てに使う Field は、この面ではレイアウトの箱でしかない。部品の既定が持つ `role="group"`
は、名前を持たない境界を支援技術へ増やすだけなので打ち消す。自動監査は名前の無い group を違反にしない
ため、面の側の検査で固定する。

**画面に出す言葉は、同じものを同じ名前で呼ぶ。**
指標の札の文言は、図の題と表の列見出しに逐語でそろえる（クチコミ数）。要約の差分の組だけは「の増減」で
実数と区別する。群の名前には社内語彙を使わない（「グラフに表示する項目」）。案内の文言は、画面に出て
いない部品名で操作を指さない（可視ラベルが「店名で絞り込む」なら「絞り込む」「入力」で書く）。

目盛りの帯の幅と、要約の 3 組を何列で並べるかは §7.20 が定める。

`.kiro/specs/store-detail-trend-dashboard/research.md` の決定 D1〜D8。2026-09-18 の変更範囲の画面レビュー

### 7.20 幅と行の分け方は、装置ではなく内容から決める

**内容で幅が決まる箱に、固定の幅を与えない。** 文字を入れる箱の幅を定数で書くと、文言・書体・端末側の
文字拡大のどれが動いても古びる。しかも余った側は黙って空き、足りない側は黙って切れる。切り取りは横の
捲りにならないので、面の溢れを測る網にも掛からない。箱は内容に追随させ、追随していることは
「内容を変えたときに箱の幅も変わるか」で確かめる。

**段組みを切り替える境目は、中身が折れる幅を実測して決める。** 装置の幅の既定の段で切ると、同じ装置でも
入れ子の深さが違う面で結果が食い違う。問い合わせ先は装置ではなく容器にする。版面とカードの内側の余白を
引いた幅が、その一覧が実際に使える幅だからである。問い合わせ先は名前で宣言し、無名にしない
（無名だと、後から祖先にコンテナが増えたときに問い合わせ先が黙って乗り換わる）。実測した数値はここへ
書かず、その値以上で最も狭い名前付きの段を選んで書く（§7.8 と同じ理由による）。
**「中身」には値だけでなくラベルも含む。** ラベルを値の上へ積む組では、ラベルだけが折れるとその組の値が
1 行ぶん下へ落ち、並んだ組の値の高さがそろわなくなる。読みやすさのために段を詰めて、その目的の側を
壊すことになるので、詰めない。

**中央寄せの短い案内は、行の長さをそろえて分ける。** 中央寄せの 1 文が最終行だけ極端に短く割れると、
文の重心が消える。最終行の孤立語だけを避ける指定ではなく、全行をそろえる指定を使う。複数段落を持ちうる
長文の受け口は別で、そちらは狭い幅でそろえ、広い幅では孤立語だけを避ける（行をそろえる指定は行数の
上限を超えると効かなくなるためである）。行の分け方は部品が持ち、面は書かない。
由来: [#286](https://github.com/ManatoYamashita/fw-line-meo/issues/286) の項目 2・3・5

## 10. Known Gaps

**原典の「display の太さを控えめに保つ」は再現できない。** システム日本語フォントは実質 400 と 700 の
2 段しか持たず、中間の太さは近い方へスナップする。意匠として再現不能であり、
Web フォントを採るなら唯一の実質的な動機になる。

**アクション色と危険色は色では区別できない。** 原典のパレットは暖色一色であり、両者の色相差は
約 14 度、相互コントラストは §2.2 の表のとおり 1.349 しかない。差し替え前の緑と赤の組でも
相互比は近い値だったので、両者を分けていたのは輝度ではなく色相であり、その色相差が失われた。
成功色に入れた色相分離の不変条件はここへ適用できない（危険色を暖色から外すと危険に読まれなくなる）。
実害が出るのは選択済みの面をアクション色で塗る部品だけで、面が透明な部品はエラー時に枠色が
中立の灰から赤へ変わるため枠が信号を運べる。前者では枠が運べないため、エラーリングの不透明度を
SC 1.4.11 を満たす段まで引き上げてある。

**副次面の上のアクション色と成功色は AA に届かない。** §2.2 の該当 2 行が示すとおり
4.5:1 を下回る。現行の部品にこの組み合わせは存在しないが、副次面の上に文字色として
これらを置く構成を採るなら再検証が要る。

**淡い面の上の危険通知は AA を割る。** §2.2 の該当行のとおりで、現状 3 面のページ背景は
いずれも白なのでこの重なりは発生しない。

**装飾専用色は通常の文字の閾値に届かない。** §2.2 の該当行のとおりページ背景に対して 3.516 であり、
SC 1.4.3 の 4.5:1 を満たさない。この色は大きい文字としてのみ用いる。面の側で使うのは
ワードマーク 2 箇所（管理ダッシュボードの帯とログイン画面）だけであり、そこは大きい文字である。
通常の文字と、文字を載せる面には §2.1 の用途欄のとおり使わない。

**文字サイズには「トークンから生成 CSS へ」の突き合わせが存在しない。** 名前空間の網羅ガードは
theme.css の宣言側しか見ないため、アプリ層がトークンに無い段を使っても赤くならない。
唯一の例外は `@layer base` の見出しが使う段で、これはトークン参照であることと実寸があることの
両方を要求される。
