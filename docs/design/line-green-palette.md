# 配色の判断（LINE の緑系）

Web の 3 面（survey-web / store-detail / dashboard-web）のブランド色・アクション色・hover を、
原典（Airbnb）の赤系ではなく LINE の緑系から採った判断の記録である。値と実測比の読み物は
`docs/design/design-language.md` §2 にあり、値の正典は `ts/packages/design-tokens/src/colors.ts` である。
本書は「なぜその値か」と「何を確かめたか」だけを持つ。

## 変えたもの・変えなかったもの

| 区分 | 対象 |
|---|---|
| LINE の緑系から採る | `brand` / `primary` / `primaryHover` |
| 原典の写像のまま | 中立色（`text` / `textBody` / `textMuted` / `background` / `surface*` / `border*`）、`success`、`destructive*`、余白・角丸・影・見出し階層・部品の構造 |
| 外部規定で値が決まる | `attribution`（Places API）、`googleSignIn*`（Sign in with Google） |
| 対象外 | LINE Flex Message の `lineColors`（`design-language.md` §7.12 のとおり LINE 面の配色は凍結） |

## 決めた値

| 役割 | 値 | 決め方 |
|---|---|---|
| `brand` | `#06C755` | LINE Green そのもの |
| `primary` | `#047733` | `brand` の各成分を 0.6 倍 |
| `primaryHover` | `#035F29` | `primary` の各成分を 0.8 倍（hover は暗くする方向で作る） |

OKLCH の色相は 3 色とも 149〜150 度で、同じ緑の濃淡として揃っている。

## 判断

**`brand` は文字に使わない。** LINE Green は白背景に対して 2.256 で、通常の文字の 4.5:1 どころか
大きい文字の 3:1 にも届かない。明るさを落として 3:1 に届かせる案（各成分 ×0.85 前後）もあったが、
LINE Green そのものではなくなるので採らなかった。ワードマークの面の役割と公開トップの見出しは、
文字色を `primary` へ移した。

**`primary` は副次面の上でも AA を満たす濃さにする。** 各成分 ×0.65 の `#048137` は白に対して 5.0 あるが、
副次面（`surfaceStrong`）の上で約 4.47 となり AA を割る。×0.6 なら副次面の上でも 5.081 を保つので、こちらを採った。

**`success` は値を変えない。** 成功色 `#15803D` とアクション色は、色相の差が 1 度未満、相互比が 1.134 で、
色だけでは見分けられない。成功色だけを青緑（`#007863` 前後）へ逃がす案もあったが、「色以外は変えない」方針に
沿って値は据え置いた。その代わりに、成功の表示はすべて印と文言を伴わせる。Alert の成功の変種は部品が印を描き、
部品を使わない成功の表示は同じ印を自前で置く。全件の照合は `ts/packages/ui/test/success-cue.test.tsx` が担う。

**アクション色と危険色の区別は、引き続き色以外の手がかりに頼る。** 両者の色相は約 116 度離れたが、
相互比は 1.160 で、緑と赤はもっとも多い色覚特性（2 型）で見分けにくい。選択済みの面をアクション色で塗る部品の
エラーリングに 3:1 を要求する検証（`ts/packages/ui/test/contrast-usage.test.ts`）は外さない。

## 画像

アイコンと OGP 画像には生成元（ベクター画像やスクリプト）が無く、ラスタ画像だけがある。色は次の方法で揃えた。

| 画像 | 揃え方 |
|---|---|
| 店舗のアイコン（各面の `icon.png`・`apple-icon.png`、管理ダッシュボードの `brand-icon.png`） | OKLCH で赤系（色相 340〜45 度・彩度 0.02 以上）の画素だけを `brand` の色相（148.6 度）へ移す。明るさと彩度は保ち、緑で出せない彩度だけを色域の端へ寄せる。透過はそのまま |
| OGP 画像（各面の `ogp.jpg`・`ogp.webp`） | アイコンと画面写真は上と同じ方法で移す。「集客AIアシスタント」の文字は、背景からの被覆率を保ったまま `primary` で描き直す |
| 公開トップの画面写真（survey-web の `screenshots/survey.png`・`draft.png`） | 色を移さず、`docs/design/public-landing-page.md` の撮影手順で実画面を撮り直す |

OGP 画像の文字を色相の移動だけで済ませなかったのは、明るさを保ったまま緑へ移すと対背景比が約 2.9:1 になり、
大きい文字の 3:1 を割るためである（赤のときは約 3.05:1）。公開トップは `ogp.webp` をそのまま画面に載せているので、
画像の中の文字も文字として扱う。`primary` で描き直した文字は約 5.4:1 になる。

画像を作り直すときは、アイコンの面と装飾には `brand` の系統を、文字には `primary` を使う。

## 確かめた一次情報

| 確かめたこと | 原文の記述 | 出典 |
|---|---|---|
| `#06C755` が LINE の緑か | LINE ログインボタンの基本色として `#06C755` を指定している。適用範囲はログインボタンで、サービス全体のブランドカラーの定義ではない | [LINEログインボタン デザインガイドライン](https://developers.line.biz/ja/docs/line-login/login-button/) |
| ブランド資産を使ってよいか | 事前承諾の無いブランド資産の使用は禁止。事前承諾が要らないのは列挙されたもの（LINE のサービスアイコン等）だけで、色・色値への言及は無い | [LINEヤフー 商標・ブランドの使用に関するガイドライン](https://www.lycorp.co.jp/ja/company/trademarks/) |
| 色の変更・配色の禁止 | 禁止されているのはロゴの改変と、「LINE」の部分だけ色や大きさを変えて強調すること。ロゴ以外でブランドカラーを使うことへの言及は無い | [LINEヤフー for Business ロゴガイドライン](https://www.lycbiz.com/jp/logo/) |
| LINE の緑が色彩のみからなる商標として出願・登録されているか | 出願・登録は無い。LINEヤフー名義の色彩のみからなる商標は 2 件（商願2015-030708 の紫・商願2015-030709 の黄）で、どちらも旧ヤフー株式会社の出願であり、拒絶で確定している | [J-PlatPat 商標検索](https://www.j-platpat.inpit.go.jp/t0100)（2026-10-12 照会） |

J-PlatPat の照会条件は、商標のタイプ「色彩のみからなる商標」・ステータス「全て」・対象文献「全て」である。
権利者「LINEヤフー」で引いた 2 件に加え、権利者を指定せずに全件（594 件）を引いて、権利者名に LINE・ヤフー・
NAVER を含むものがこの 2 件だけであることを確かめた。色彩のみからなる商標の出願受付は 2015 年 4 月 1 日に
始まったので、全件は制度開始からの全出願にあたる。

確かめた範囲で、自社の画面の配色に LINE Green とその濃淡を使うことを禁じる記述は無かった。
LINE のロゴ・アイコン・ログインボタンは使っていない。

## 守ること

- 将来 LINE ログインボタンを置くなら、そのボタンだけはガイドラインの規定色（`brand` と同値）で描く。
  `primary` で描くと規定外の色になる。
- LINE 公式の画面と誤認させる要素（LINE のロゴ・アイコン・名称を主役に据えた表示）を Web 面に置かない。
- 成功色を色相で分ける変更をしても、成功の表示の印と文言は外さない。
