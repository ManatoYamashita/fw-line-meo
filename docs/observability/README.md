# 観測性の文書

## この階層にあるもの

- `log-field-canon.md` — 記録の項目名と事象名の**正典**。意味と各実行面での名前の対応を定める唯一の場所

## なぜ正典が要るか

応答層（TypeScript）と日次バッチ層（Go）は同じ集約基盤へ記録を出すが、**項目名を全実行面で同一の文字列へ統一することはできない**。本番の集計指標が参照する表記と、既存 spec が要求仕様として名指しする表記が、それぞれ別の流儀で固定されているためである。

言語をまたぐためコードで共有することもできない。したがって steering `structure.md` の「codegen は持たず、手動同期を機械検証で固める」に従い、**宣言（正典）と実装を機械的に両方向照合する**形をとる。

## 項目や事象名を追加するとき

1. `log-field-canon.md` の該当する節へ行を足す
   - **該当がない欄は空にせず `該当なし` と書く**。空欄を許すと、棚卸しの漏れが「行が無い」という不可視の形になる
   - 由来は `新規`。**新規の項目名は全実行面で同一の名前にする**（既存の分岐は固定したまま、前方だけ統一する）
   - 出典には、その名前が実際に現れる実装ファイルのリポジトリ相対パスを書く
2. 実装側に同じ名前で追加する
3. 次を通す

```bash
bash scripts/check-log-field-canon.sh     # 正典自身の構造
bash scripts/check-log-field-binding.sh   # 正典と実装の両方向照合
bash scripts/check-log-sink-usage.sh      # 共有経路を通らない出力の検出
```

## 記録してはならない値

来店客の入力（自由記述・生成された下書き本文・生成指示）、オーナーを外部プラットフォーム上で一意に識別する値、来店客を複数の記録にまたがって同一人物と判定できる値。

これらは共有パッケージの型として**持たない**。持たないものは漏れない。個々の実装者の注意力ではなく構造で守る（`.kiro/steering/product.md` の不可侵の前提）。
